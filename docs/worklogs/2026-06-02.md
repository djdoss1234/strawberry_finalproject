## 오늘 확인한 핵심 변경점

### 1. 카메라 중심 → 그리퍼 중심 스캔 자세로 전환

기존 자세는 카메라 정면 앵글 기준으로 각 셀을 잘 보이게 만드는 데 초점이 있었다.
하지만 실제 수확에서는 카메라가 셀 중앙을 잘 보더라도, 그리퍼가 줄기/과실에 접근하기 어려우면
pick motion에서 관절 한도, wrist wind-up, 과도한 우회 동작이 발생한다.

그래서 2026-06-01에 네 셀 전체를 다시 티칭했다. 새 기준은 다음과 같다.

- 카메라는 셀과 딸기 후보를 충분히 볼 것
- 그리퍼 finger/tip이 셀 중심 작업 영역과 수평에 가깝게 정렬될 것
- 후속 grasp 접근이 가능한 로봇 자세일 것

이 변경은 perception 모델 변경이 아니라 **task frame / motion feasibility correction**이다.

### 2. 15.8cm 딸기 파지 파츠 장착

그리퍼에는 약 15.8cm 길이의 3D 프린터 출력 파지 파츠가 장착되었다.
따라서 카메라 optical center만 기준으로 포즈를 잡으면 실제 파지점과 작업 중심이 어긋날 수 있다.
v12 포즈는 이 물리적 tool extension을 고려해, 카메라 시야와 그리퍼 접근성을 함께 맞춘 포즈다.

주의: 파츠 장착 후 tool collision sphere / TCP offset / gripper 접근 bias는 다시 검증해야 한다.

### 3. Cartesian TCP 조그와 자동 스캔 실행 경로 구분

대시보드/수동 조작에서는 TCP 기준 Cartesian 직선 조그를 사용해 미세 조정할 수 있다.
이 조그는 사람이 화면을 보며 셀 중심, 그리퍼 정렬, 접근 여백을 맞추는 티칭/검증 도구다.

반면 현재 자동 스캔 순회는 아직 각 셀의 `endpoint_joints_deg`를 직접 보내는 `MoveJoint` 기반이다.
즉, 지금 동작은 다음 구조다.

```text
DART/dashboard 수동 조정으로 셀별 목표 TCP/관절 pose 티칭
 -> YAML endpoint_joints_deg 저장
 -> scan_executor가 셀 순서대로 MoveJoint 실행
 -> J1/J4/J6은 같은 물리 자세의 360deg equivalent 중 현재 관절에서 가까운 값을 선택
```

### 4. Joint equivalent rewrite 적용

DART는 같은 물리 wrist 자세를 `J4=-238.5deg`처럼 기록할 수 있다.
하지만 로봇이 현재 `J4=175.9deg` 근처에 있으면, 같은 자세인 `J4=121.5deg`로 보내는 것이 훨씬 짧다.

`scan_executor_node.py`는 J1/J4/J6에 대해 다음을 수행한다.

1. YAML의 원본 티칭값은 유지한다.
2. 실행 직전 현재 `/joint_states`를 읽는다.
3. `target + k*360deg` 후보 중 로봇 hard limit 안에 있고 현재 관절에서 가장 가까운 값을 선택한다.
4. arrival check도 실제 전송한 equivalent joint 기준으로 수행한다.

이 덕분에 불필요하게 뱅글뱅글 도는 wrist 표현 문제를 줄이고, 다음 셀로 넘어가지 않는 arrival mismatch도 방지한다.

### 5. cuRobo branch 최적화 원리

수동 티칭한 TCP pose가 하나 있어도, 6축 로봇에서는 같은 TCP pose를 만드는 IK branch가 여러 개 있을 수 있다.
cuRobo 최적화 스크립트는 다음 방식으로 동작한다.

```text
각 셀의 tcp_transform_base 고정
 -> cuRobo IK로 가능한 joint branch 후보 생성
 -> 후보마다 관절 한도 압박, 수동 티칭과의 차이, 현재/이전 셀과의 이동량 계산
 -> scan order 전체를 그래프로 보고 동적 계획법으로 총 전이 비용이 작은 branch 조합 선택
```

현재 비용 항목:

- `l1_delta`: 전체 관절 변화량
- `max_delta`: 한 관절에 몰린 최대 변화량
- `wrist_delta`: J4/J6 wrist 회전량
- `limit_pressure`: 관절 한도 근접 penalty
- `taught_deviation`: 수동 티칭 자세에서 벗어나는 정도

결과 파일:

- `docs/runs/RUN-20260602-001_curobo_scan_branch_optimization.yaml`

현재 dry-run 결과는 일부 셀에서 더 짧은 branch 후보를 찾았지만, 아직 바로 적용하지 않았다.
이유는 exact TCP pose만 고정하면 후보 수가 제한되고, collision world/tool sphere가 현재 15.8cm 파지 파츠와 완전히 맞는지
재검증이 필요하기 때문이다.

### 6. runtime cuRobo preview

`enable_runtime_curobo_preview:=true`를 켜면, scan_executor가 셀 이동 직전에 현재 joint state 기준 cuRobo plan을 계산해
YAML MoveJoint와 비교 로그를 남긴다.

중요한 현재 정책:

- preview는 진단용이다.
- 로봇 실행은 여전히 검증된 YAML MoveJoint pose를 사용한다.
- preview는 백그라운드 thread에서 돌며, 로봇 이동을 막지 않는다.
- 이전 preview가 아직 돌고 있으면 다음 preview는 스킵한다.

오늘 관찰:

- preview를 blocking으로 돌렸을 때 NE→SE 전환에서 수 초 딜레이가 발생했다.
- 이를 비동기 preview로 바꿔 셀 전환 딜레이를 제거했다.
- preview 실패 로그 중 `INVALID_START_STATE_SELF_COLLISION`, `INVALID_START_STATE_WORLD_COLLISION`은 실제 MoveJoint 실패가 아니라
  cuRobo collision world/tool model 기준 진단 실패다.

## 실제 검증 관찰

명령:

```bash
ros2 launch strawberry_motion workspace_scan.launch.py \
  enable_robot_execution:=true \
  target_cell:=all \
  enable_pick_integration:=false \
  enable_runtime_curobo_preview:=true \
  runtime_curobo_preview_retries:=2 \
  scan_movej_vel_deg_s:=60.0 \
  scan_movej_acc_deg_s2:=90.0
```

관찰:

- 4셀 순회는 MoveJoint로 완료됨.
- 셀 간 overview reset 없이 `INTER_CELL_DIRECT`로 다음 셀 이동.
- J4/J6 equivalent rewrite가 적용되어 실제 전송 joint가 더 짧은 branch로 바뀜.
- preview cuRobo는 일부 셀에서 collision diagnostic 실패를 냈지만, 실제 YAML MoveJoint 실행은 정상 완료.
