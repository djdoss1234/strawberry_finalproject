## SW MoveSplineJoint Silent No-Motion 대응

- 현상:
  - `root/sw` 단일 실행에서 cuRobo plan은 `PLAN_VALID`.
  - endpoint: `[149.6, 1.1, 142.6, -124.0, 93.6, 58.7]`
  - `/dsr01/motion/move_spline_joint` 응답은 `success=True`.
  - 하지만 실제 로봇이 움직이지 않아 `EXEC_TIMEOUT` 발생.
  - 동일 환경에서 `MoveJoint` overview return은 정상 동작.

- 해석:
  - planner/IK 실패가 아니라 Doosan `MoveSplineJoint`가 특정 SW joint
    spline을 조용히 수락만 하고 실제 motion을 시작하지 않는 실행 계층
    문제로 분리.
  - `MoveSplineJoint` 응답에는 `msg` 필드가 없으므로 `msg='N/A'`는
    내부 rejection 메시지가 아님.

- 조치:
  - `root/sw`에만 저속 spline probe 적용.
    - velocity: `20 deg/s`
    - minimum request time: `15 s`
  - spline 응답 후 `5 s` 동안 현재 joint가 시작점에서 `2 deg` 이내이면
    silent no-motion으로 판단.
  - silent no-motion일 때 SW endpoint로 저속 `MoveJoint` fallback 실행.
    - velocity: `15 deg/s`
    - acceleration: `20 deg/s^2`
  - fallback 후에도 기존 endpoint 도착 확인 로직을 유지.

- 검증:

  - `pytest`: `52 passed`
  - `git diff --check`: 통과

## 기록 보강

- SW 도달 실패는 중요한 troubleshooting case로 분리 기록했습니다.
- issue:
  `docs/issues/ISSUE-20260528-008_sw_plan_valid_execution_no_motion.md`
- run:
  `docs/runs/RUN-20260528-002_sw_execution_no_motion.md`
- 핵심 메시지:
  - cuRobo `PLAN_VALID`는 실제 controller execution success가 아니다.
  - Doosan service `success=True`도 실제 arrival success가 아니다.
  - 실제 성공 판정은 joint-state arrival check로 해야 한다.

- 주의:
  - SW `MoveJoint` fallback은 cuRobo의 전체 spline path를 그대로 실행하는
    것이 아니라 endpoint joint move로 우회하는 것이다.
  - 따라서 첫 실기 검증은 저속, clear-space, E-stop 준비 상태에서만 수행한다.
